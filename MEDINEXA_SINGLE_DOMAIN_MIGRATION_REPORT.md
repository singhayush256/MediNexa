## 7. Centralized Configuration Architecture

### 7.1 Frontend (`apps/web/lib/domain-config.ts`)
```typescript
export const OFFICIAL_PRODUCTION_FRONTEND_URL = 'https://medinexa-medicalweb.vercel.app';
export const OFFICIAL_PRODUCTION_BACKEND_URL = 'https://medinexa-duplicate-api.onrender.com/api/v1';

export function getAppBaseUrl(): string {
  const envUrl = process.env.NEXT_PUBLIC_APP_URL?.trim();
  if (envUrl && envUrl.length > 0) return envUrl.replace(/\/$/, '');
  if (typeof window !== 'undefined') return window.location.origin;
  if (process.env.VERCEL_URL) return `https://${process.env.VERCEL_URL.replace(/\/$/, '')}`;
  if (process.env.NODE_ENV === 'production') return OFFICIAL_PRODUCTION_FRONTEND_URL;
  return 'http://localhost:3000';
}
```

### 7.2 Backend (`apps/api/src/common/utils/domain-config.util.ts`)
```typescript
export const OFFICIAL_PRODUCTION_FRONTEND_URL = 'https://medinexa-medicalweb.vercel.app';
export const OFFICIAL_PRODUCTION_BACKEND_URL = 'https://medinexa-duplicate-api.onrender.com/api/v1';

export function getFrontendBaseUrl(): string {
  const envUrl = process.env.FRONTEND_URL || process.env.APP_URL;
  if (envUrl && envUrl.trim().length > 0) return envUrl.trim().replace(/\/$/, '');
  if (process.env.NODE_ENV === 'production') return OFFICIAL_PRODUCTION_FRONTEND_URL;
  return 'http://localhost:3000';
}
```

## 8. CORS and Authentication Changes

### 8.1 CORS Whitelist
The CORS policy in `apps/api/src/common/utils/cors-origin.util.ts` enforces strict origin matching:
1. Origin in `process.env.CORS_ORIGIN` (which begins with `https://medinexa-medicalweb.vercel.app`).
2. Enterprise domains: `medinexa.com`, `medinexa.health`, `medinexa.in` (and subdomains).
3. Explicit deployment origins:
   - `medinexa-medicalweb.vercel.app` (Primary official frontend)
   - `medinexa-duplicate.vercel.app` (Retained for seamless backward-compatibility)
   - `medi-nexa-web-nu.vercel.app` (Staging origin)
   - `medinexa-web.vercel.app`
   - `medinexa.vercel.app`
4. Wildcards (`*`) remain strictly prohibited in production mode.
5. Untrusted origins (e.g. `https://attacker-phishing.vercel.app`) are rejected with HTTP 403 / CORS block.

### 8.2 Authentication Security
- Tokens are issued with `JWT_EXPIRES_IN=8h` (matching standard hospital shift lengths).
- Authentication cookies/headers operate with `credentials: true`.
- Zero open redirects or untrusted Host header reliance.

## 15. Remaining Vercel-Generated URLs

- Vercel automatically creates ephemeral deployment URLs for every Git commit (e.g., `medinexa-duplicate-git-main-*.vercel.app`). These URLs are intrinsic to Vercel's immutable deployment infrastructure and are **not deleted**.
- By implementing `getAppBaseUrl()` in `apps/web/lib/domain-config.ts`, preview deployments dynamically bind to their own preview origin for testing, while production traffic canonically resolves to `https://medinexa-medicalweb.vercel.app`.

## 16. Known Limitations

1. **Render Free-Tier Cold Starts:** When idle, the Render free-tier container may spin down, taking 30–50 seconds to wake on the initial request. Client fetch requests include a 45-second timeout and automated pre-warming (`warmUpBackend()`).
2. **Upstash Redis Reconnection:** The production Render web service currently operates in `memory_fallback` mode until the operator re-enters the active `REDIS_URL` in the Render dashboard.
