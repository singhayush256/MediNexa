# MediNexa Day 6 Architecture: Patient Admission, Discharge, & Transfer Engine

## 1. Architectural Model & Entity Hierarchy

MediNexa enforces a strict distinction between clinical admissions and operational bed assignments:

```
PatientProfile (1) ───< Admission (N) ───< BedAssignment (N) ───> Bed (1)
                            │
                            ├───< AdmissionTransfer (N)
                            │
                            └───< AdmissionStatusHistory (N)
```

- **`Admission`**: Primary clinical container representing a patient's inpatient stay at a facility.
- **`BedAssignment`**: Operational occupancy link generated by `AdmissionService` calling `BedService.assignBed()`. Associated with the `Admission` via `admissionId`.
- **Lifetime History**: A patient may have multiple admissions over time (`PLANNED`, `ADMITTED`, `TRANSFERRED`, `DISCHARGE_PENDING`, `DISCHARGED`, `CANCELLED`). An admission may contain multiple bed transfers.

---

## 2. Admission Lifecycle State Machine

```
PLANNED ──> ADMITTED
PLANNED ──> CANCELLED
ADMITTED ──> TRANSFERRED
ADMITTED ──> DISCHARGE_PENDING
TRANSFERRED ──> DISCHARGE_PENDING
DISCHARGE_PENDING ──> DISCHARGED
```

- Status changes are controlled through strict transition guards.
- Retransitioning from `DISCHARGED` back to `ADMITTED` is rejected with `409 Conflict`. A new admission must be created for future visits.

---

## 3. Atomic Multi-Step Transaction Strategy

To guarantee strict relational integrity across multi-step operations:

1. **Admission Creation + Initial Bed Assignment**:
   - `prisma.$transaction` creates `Admission` record and calls `BedService.assignBed`.
   - If initial bed assignment fails (e.g. bed not available/conflict), the entire transaction rolls back.

2. **Patient Discharge**:
   - `prisma.$transaction` updates `Admission.status` to `DISCHARGED`, records `dischargedAt`, calls `BedService.releaseBed` (releasing `BedAssignment` and setting `Bed.status` to `CLEANING`).

3. **Bed Transfer Engine**:
   - `prisma.$transaction` calls `BedService.releaseBed` for old bed (`CLEANING`), calls `BedService.assignBed` for target bed (`OCCUPIED`), creates `AdmissionTransfer` audit log, and updates `Admission.status` to `TRANSFERRED`.
   - Concurrent transfer attempts for the same target bed trigger Day 5 atomic state locks, resulting in `1 SUCCESS (200/201)` and `1 CONFLICT (409 Conflict)`.
